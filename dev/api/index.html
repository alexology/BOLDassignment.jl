API

BOLDassignment.BOLDassignment — Module
BOLDassignment

Taxonomic assignment of amplicon sequence variants (ASVs) against the BOLD v5 identification engine (https://id.boldsystems.org).

Sequences are submitted through the documented Barcode ID API, the hits are returned as a long table (bold_identify) and a lowest common ancestor with a minimum agreement percentage turns them into one assignment per sequence (lca_assign). bold_assign runs both steps on a DataFrame with an ASV column. bold_records retrieves record metadata from the BOLD portal API.

One-call assignment

BOLDassignment.bold_assign — Function
bold_assign(df::AbstractDataFrame; sequence_col = :ASV, hits = nothing, prefix = "",
            db = :animal_public, mode = :rapid, engine = IDEngine(),
            chunk_size = nothing, checkpoint = nothing, lca_kwargs...) -> DataFrame

Assign a taxonomy to the sequences in column sequence_col of df.

Unique sequences are identified with bold_identify (or taken from a previously computed hits table, without network access) and assigned with lca_assign; lca_kwargs (min_agreement, thresholds, top_delta, ignore_missing, valid_name, ranks, direction) are passed to it. With direction = :bottom_up the columns decision_rank and lineage_conflict are appended as well. Every row of df is kept, in order, with the assignment columns appended, their names preceded by prefix. Rows with a missing sequence get missing assignments.

Example

asvs = DataFrame(ASV = ["ACTTTATATTTTATTTTTGGAATTTGAGCAGGAATAGTAGG..."])
hits = bold_identify(asvs.ASV; checkpoint = "bold_cache")
tax = bold_assign(asvs; hits, min_agreement = 90)

Identification

BOLDassignment.bold_identify — Function
bold_identify(sequences; db = :animal_public, mode = :rapid, engine = IDEngine(),
              chunk_size = nothing, checkpoint = nothing) -> DataFrame

Identify sequences with the BOLD identification engine and return all hits as a long table.

Sequences are normalized with normalize_sequence, submitted once each and grouped in chunks of at most chunk_size (default: the maximum documented for mode, see BOLD_MODES) after sorting. With checkpoint set to a directory, the raw result of each sequence is saved there (one file per sequence, database and mode) and reused by later calls, so an interrupted run resumes where it stopped and adding sequences submits only the new ones. A checkpoint file that cannot be read back is reported and its sequence submitted again. db is a key of BOLD_DATABASES or an API code.

If a finished submission lacks the result of some sequences, they are reported with a warning, returned without hits with result_received = false and not saved in the checkpoint, so a later call submits them again.

Columns: sequence (normalized), process_id, bin_uri, record_status, similarity (percent, 100 - pdist), marker (e.g. COI-5P), taxid (BOLD taxonomy ID), align_length (length of the alignment) and query_coverage (percent of the query covered by the hit: qcovhsp, or computed from qstart/qend), result_received (false when BOLD did not return the result of the sequence: unknown, not "no match"), and one column per rank in RANKS. A sequence without hits has one row with missing hit fields. Rows follow the sorted order of the sequences.

Client

BOLDassignment.IDEngine — Type
IDEngine(; kwargs...)

Connection settings for the BOLD Barcode ID API.

The API documents at most 3 submissions and 40 status or result requests per minute; going over may block the client for a while. The defaults stay below both limits. The spacing is shared by all engines using the default throttle, so consecutive or concurrent calls respect the limits together.

Keywords

  • base_url = "https://id.boldsystems.org"
  • submit_interval = 21.0: minimum seconds between two submissions.
  • request_interval = 1.6: minimum seconds between two status/result requests.
  • status_wait = 15.0: seconds between two status checks of the same submission.
  • max_active = 5: submissions waiting for results at the same time.
  • timeout = 3600.0: seconds after which an unfinished submission is resubmitted.
  • max_resubmits = 3: resubmissions of one chunk before giving up.
  • max_retries = 8: consecutive failures tolerated for one request.
  • retry_wait = 30.0: wait after a failure, multiplied by the attempt number.
  • request: function (method, url, payload) -> (status, body) performing the HTTP request; payload is nothing or the FASTA bytes. Replaceable in tests.
  • sleep, time: clock functions, replaceable in tests.
  • throttle: request spacing state; pass BOLDassignment._Throttle() for an independent one (tests).
  • verbose = true: print progress messages.

LCA

BOLDassignment.is_valid_name — Function
is_valid_name(rank, name) -> Bool

Whether name is a usable identification at rank. A species must be a Latin binomial (optionally with subgenus in parentheses or a subspecies epithet) without open nomenclature: names such as Onthophagus sp., Onthophagus sp. 1, Onthophagus cf. taurus, Onthophagus aff. taurus or interim codes (Diptera sp. BIOUG1234-A01) are rejected. Other ranks must be a single capitalized word without digits, and not a placeholder such as Unknown. missing is never valid.

BOLDassignment.lca_assign — Function
lca_assign(hits::DataFrame; min_agreement = 100, thresholds = DEFAULT_THRESHOLDS,
           top_delta = Inf, ignore_missing = true, valid_name = is_valid_name,
           ranks = RANKS, direction = :top_down) -> DataFrame

Apply lca_path to every sequence of a hit table returned by bold_identify.

One row per sequence, in order of first appearance, with columns sequence, n_hits, best_similarity, best_process_id, assigned_rank, taxon (deepest assigned taxon), one column per rank with the assigned name and one <rank>_agreement column with the percent of pool hits supporting it. Unassigned ranks are missing; a sequence without hits has n_hits = 0.

With direction = :bottom_up (see lca_path) two columns follow: decision_rank, the rank decided by its own pool (equal to assigned_rank, missing when nothing is assigned), and lineage_conflict, true when the supporting hits disagree or lack a valid name at a rank above it. For the ranks above the decision rank, <rank>_agreement is the percent of supporting hits carrying that name, not a share of the rank's pool. With the default :top_down the columns are exactly as in earlier versions.

BOLDassignment.lca_path — Function
lca_path(similarity, lineages; min_agreement = 100, thresholds = DEFAULT_THRESHOLDS,
         top_delta = Inf, ignore_missing = true, valid_name = is_valid_name,
         ranks = RANKS, direction = :top_down)

Lowest common ancestor of the hits of one sequence with a minimum agreement. direction = :top_down (default) descends from the most general rank, as described first; direction = :bottom_up starts from the most specific rank and moves up (see below).

similarity holds the percent similarity of each hit and lineages one indexable lineage per hit (lineage[r] for each rank r in ranks, missing when unknown). Ranks are visited from the most general to the most specific. At rank r the pool contains the hits with similarity at least thresholds[r] and at least maximum(similarity) - top_delta. The most frequent taxon at r among the pool hits that agree with the ranks already assigned is accepted when it is supported by at least min_agreement percent of the pool; otherwise the assignment stops at the previous rank. Ties for the most frequent taxon stop the assignment.

With min_agreement = 100 (default) this is the strict LCA of the pool. The default top_delta = Inf keeps every hit above the rank threshold, the conservative choice; a finite value restricts the pool to the closest hits. thresholds may list only some ranks: the others keep DEFAULT_THRESHOLDS. A rank without a default threshold must be given one.

Hits not identified at r, i.e. with a missing name or one rejected by valid_name(r, name) (default is_valid_name), leave the pool at that rank and at the deeper ones: a record of Onthophagus sp. or Onthophagus cf. taurus above the species threshold does not take part in the species decision but still supports the genus. With ignore_missing = false such hits stay in the pool and count against the agreement.

Returns a vector of (rank, taxon, agreement, n_support, n_pool) named tuples, one per assigned rank from the most general to the most specific (empty when nothing can be assigned).

Bottom-up direction

With direction = :bottom_up the ranks are visited from the most specific to the most general, and the decision rank is the first one whose pool agrees. The pool of a rank is defined as above. Only hits with a valid name at that rank vote; with ignore_missing = true the others leave the pool of that rank, with ignore_missing = false they stay in it and count against the agreement. Unlike the top-down direction, every rank is judged on its own: a hit not identified at the species still votes at the genus, and the votes at a rank do not depend on the other ranks. The most frequent taxon is accepted when it is unique and supported by at least min_agreement percent of the pool; otherwise (or with an empty pool) the next more general rank is tried. When no rank agrees, nothing is assigned.

The ranks above the decision rank come from the supporting hits, the pool hits voting for the accepted taxon: at each higher rank the most frequent valid name among them is taken, even when they are not unanimous. In those entries n_pool is the number of supporting hits, n_support the number carrying the name and agreement = 100 * n_support / n_pool, so an agreement below 100 signals inconsistent BOLD classifications (e.g. one species name under two genera, or supporting hits without a name at that rank). On a tie, or when no supporting hit has a valid name, that rank and all the more general ones are left out of the path. The decision rank is the last entry and the only one to which min_agreement applies. Use top_delta = Inf (default) with this direction, so that every hit above the threshold of a rank takes part.

BOLDassignment.boldigger3_hits — Function
boldigger3_hits(hits::AbstractDataFrame; ids = nothing, metadata = nothing) -> DataFrame

The input of boldigger3_select from a bold_identify table, as BOLDigger3 builds it: one row per hit with id (the sequence, or ids[sequence] when ids maps sequences to names), the ranks, pct_identity (= similarity), process_id, bin_uri, hits sorted by decreasing similarity within each sequence (stable: BOLD's order on ties) and a "no-match" row for a sequence without hits.

Hits with equal similarity keep BOLD's order; BOLDigger3 receives them in the order of its DuckDB query, which is not defined for equal values. This only matters for the order of the BINs in BIN and for tied groups (tied_groups > 1).

metadata (optional) plays the role of BOLDigger3's local database: a table with processid and identification_method, one row per record and marker. Each hit is joined to every row of its process ID (so a record with several markers counts several times, as in BOLDigger3), status is "public" when a row was found and "private" otherwise. Without metadata, status is BOLD's record_status and identification_method is missing, so flags 1 and 3 may differ from BOLDigger3.

BOLDassignment.boldigger3_select — Function
boldigger3_select(hits::AbstractDataFrame; id_col = :id,
                  thresholds = BOLDIGGER3_THRESHOLDS, ties = :first) -> DataFrame

BOLDigger3's top-hit selection, one row per sequence (in order of first appearance in hits), with BOLDigger3's output columns: id, the ranks phylum … species, pct_identity, status, records, records_ratio, selected_level, BIN, flags, and tied_groups (added here: number of taxa sharing the highest record count at the selected level; with more than one, BOLDigger3's own choice depends on numpy's sort).

hits has one row per hit, in BOLDigger3's order (by decreasing pct_identity within each sequence), with the columns id_col, the ranks of RANKS, pct_identity, status ("public"/"private"), bin_uri and optionally identification_method; names are cleaned with boldigger3_name. A sequence whose hits contain "no-match" is reported as in BOLDigger3. boldigger3_hits builds this table from bold_identify results.

The rule, as in BOLDigger3: the highest similarity picks the starting level (thresholds: species, genus, family, order, class, phylum); the hits at or above its threshold are grouped by their names down to that level, groups without a name at that level are dropped (moving up one level if none is left) and the most numerous group wins. Its hits (all of them, also those below the threshold) give the reported record, the BINs (species level only) and the flags: 1 all identification methods name BOLD, ID, Tree or BIN; 2 the winner has under 90 % of the grouped records; 3 all its records are private; 4 a single record; 5 several BINs. ties = :first takes the first of tied groups in hit order.

Record metadata

BOLDassignment.bold_records — Function
bold_records(process_ids; fields = nothing, engine = IDEngine(), base_url =
             "https://portal.boldsystems.org") -> DataFrame

Retrieve public BOLD records (BCDM fields) for process_ids through the portal API, e.g. to add collection data to the hits of bold_identify. Only the columns in fields are kept when given; nested values (such as coord) are returned as JSON text. Unknown or private process IDs are absent from the result. Requests use the spacing, retries and transport of engine.

The portal returns one document per marker of a specimen (record_id <processid>.<marker_code>, e.g. COI-3P and COI-5P), each with its own sequence nuc. With marker = "COI-5P" only the documents of that marker are kept (case-insensitive); otherwise a process ID may appear in several rows.
